# Feasibility review

Reviewed 2026-10-23. Public documentation review is complete enough for a prototype; account-specific entitlements and tenant behavior still need controlled integration tests.

## Confirmed path and limitations

1. Office.js compose `subject.getAsync` and `body.getAsync` support subject, HTML and plain-text extraction. Use a compose command task pane; leave native Send untouched. Extraction is a snapshot, not an atomic lock on Outlook editing. Re-read before confirmation. Embedded CID images and attachments require MIME asset handling outside MVP; the pane rejects detected attachments/CID images. Ordinary externally hosted images may still be blocked by recipients. [Subject API](https://learn.microsoft.com/en-us/javascript/api/outlook/office.subject?view=outlook-js-1.1), [Body API](https://learn.microsoft.com/en-us/javascript/api/outlook/office.body?view=outlook-js-1.1).
2. Use Microsoft's NAA/MSAL pattern and a tenant-specific Entra API access token with a delegated application scope. An Outlook mailbox address, ID token, Graph token, or client-provided identity is not sufficient for this backend. NAA needs a registered SPA broker redirect, supported browser/host and consent. Unsupported hosts fail with guidance; no legacy Exchange identity-token fallback. [NAA setup](https://learn.microsoft.com/en-us/office/dev/add-ins/develop/enable-nested-app-authentication-in-your-add-in), [requirement set](https://learn.microsoft.com/en-us/office/dev/add-ins/reference/requirement-sets/nested-app-auth-requirement-sets).
3. HTTPS task-pane hosting and add-in deployment are separate from Entra consent. An add-in-only XML manifest is sufficient for this narrowly scoped Outlook web prototype. Tenant policies can disable custom add-ins; admin deployment may be required. Use trusted HTTPS locally or an authorized HTTPS test host. [Sideload instructions](https://learn.microsoft.com/en-us/office/dev/add-ins/outlook/sideload-outlook-add-ins-for-testing).
4. External submission does **not** create Exchange Sent Items. Supported add-in custom properties can persist a tracking key. This prototype writes that metadata only on the explicit Prepare action. It never deletes a draft or changes its subject/body. A prepared draft keeps its key; changing content after submission requires composing a new draft. A failure to save properties blocks preparation. Duplicating/copying a draft or stripping properties can defeat draft-level identity; server idempotency is per key, not semantic email similarity. [Custom properties](https://learn.microsoft.com/en-us/javascript/api/outlook/office.customproperties?view=outlook-js-1.1).
5. SMTP2GO HTTPS `/v3/email/send` supports sender, HTML/text and custom headers, and returns `data.email_id`. HTTP 200 alone is insufficient. The current endpoint recommends `fastaccept:true`, which omits `succeeded/failed`; the adapter explicitly sets **false** for a conservative synchronous acceptance contract. A changed/malformed contract is unknown, never automatically resent. No send-idempotency key guarantee was found in the documented standard-send schema. Custom correlation headers are not deduplication keys. [Send guide](https://developers.smtp2go.com/docs/send-an-email), [current send schema](https://developers.smtp2go.com/reference/send-standard-email).
6. Current documented free SMTP2GO allowance is **1,000/month and 200/day**, with an additional 25/hour limitation without a verified domain. This is a real constraint for time-sensitive event batches. The provider documents queueing above the daily allowance, but rejecting attempts above the monthly allowance; acceptance can therefore conceal a delay. Free accounts allow one webhook and two dashboard team members, sufficient for a single consolidated event receiver. Reporting duration is documented as **5 days free versus 30 days paid**, with extensions available. Confirm account features and retention before onboarding; this is activity reporting duration, not a guarantee of immediate erasure from all provider systems. [Rate limits and plan notes](https://developers.smtp2go.com/docs/rate-limiting), [free plan](https://support.smtp2go.com/hc/en-gb/articles/223087947-Free-Plan).
7. SMTP2GO supports processed, delivered, bounce, reject, open, click, spam and subscription events. Webhooks document `id`, `email_id`, `rcpt`, `event`, `time` and selectable custom email headers. Webhook setup supports **bearer or basic Authorization**, rather than an assumed HMAC signature. JSON is configurable; default is form. Phase 3 will require JSON + a dedicated bearer secret, deduplicate canonical event fingerprints (do not assume `id` is globally unique per occurrence), and validate controlled real payloads. Metadata is available in configured webhooks; arbitrary-header dashboard filtering/deep links remain unverified. Use stored provider `email_id` and a narrow time/recipient search in Reports > Activity. [Webhook schema](https://developers.smtp2go.com/docs/webhooks-overview), [configuration](https://developers.smtp2go.com/reference/add-webhook).
8. Queues are at-least-once, not an exactly-once email guarantee. D1 transactional batch inserts and conditional claims supply the local constraints. A DB outbox scan repairs the enqueue gap. A stale send claim becomes unknown, never queued again automatically. [Queue guarantees](https://developers.cloudflare.com/queues/reference/delivery-guarantees/), [D1 batch transactions](https://developers.cloudflare.com/d1/worker-api/d1-database/).

## Infrastructure and cost assumptions

Use one Worker with static assets, D1, one Queue and a five-minute repair trigger. Cloudflare currently documents Queues on Free with 10,000 operations/day and 24-hour retention; normal write/read/delete delivery consumes three operations. Paid includes 1M operations/month, then $0.40/M, in addition to a Workers paid subscription. D1 Free includes 5M rows read/day, 100k rows written/day and 5 GB total storage; scans and indexes affect usage. Free-tier caps can stop processing; the persisted outbox recovers after queue loss. Do not assume free infrastructure or SMTP2GO capacity is adequate for an event deadline. Recheck pricing before any deployment. [Queues pricing](https://developers.cloudflare.com/queues/platform/pricing/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/).

## Prior art reviewed

- [Microsoft samples repository](https://github.com/OfficeDev/Office-Add-in-samples) and [Hello World source](https://github.com/OfficeDev/Office-Add-in-samples/tree/main/Samples/hello-world/outlook-hello-world): Office.onReady, callback APIs and compose-command XML pattern. Manifest adapted from that MIT-licensed sample; attribution is in THIRD_PARTY_NOTICES.md.
- [Office.js issue 3971](https://github.com/OfficeDev/office-js/issues/3971): context for a custom task-pane send action; not treated as a supported mechanism to replace native Send or update Exchange Sent Items.
- [cf-mail-relay](https://github.com/alexlmiller/cf-mail-relay): Worker boundary pattern; its Docker SMTP relay, Cloudflare sending provider and admin application are outside this scope. No implementation imported.

## Policy implications

Event instructions may be transactional depending on primary purpose; promotional content can change that classification. Keep accurate identity/contact details and legitimate customer relationships. SMTP2GO's mailing-list rules may impose requirements beyond CAN-SPAM's transactional exceptions. Obtain provider confirmation of the intended operational-group workflow before production; do not interpret a purchase as blanket marketing consent. [SMTP2GO acceptable use](https://www.smtp2go.com/terms/), [FTC primary-purpose guidance](https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business).
